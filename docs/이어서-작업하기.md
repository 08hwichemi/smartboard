## 지금 막 끝낸 일 (2026-09-26.14) — 교사 역할(담임/부장/교감/교장/실무자) 지정 기능 추가

여러 세션 전부터 미뤄뒀던 "교사 역할 지정" 기능을 드디어 만들었습니다. 사용자 요청:
"관리자 설정에서 교사들 역할을 담임, 부장, 교감, 교장, 실무자로 하고 담임인 경우에는
학년, 반 누를 수 있게 세팅하자." — 단, "실무자는 홈화면을 다르게 구성할거라서 이건 나중에
이야기 하고"라고 명시했으므로, **역할 지정 자체만** 만들었고 역할에 따라 화면을 다르게
보여주는 로직(실무자 전용 홈화면 등)은 **이번에 만들지 않았습니다** — 다음에 논의 후
착수해야 합니다.

### DB 변경 (Supabase 마이그레이션 `add_teacher_role_and_homeroom`)
- `teachers` 테이블에 `role text`(체크 제약: `담임`/`부장`/`교감`/`교장`/`실무자`만 허용,
  NULL 허용 = 미지정), `homeroom_grade smallint`, `homeroom_class smallint` 추가.
- 체크 제약 `teachers_homeroom_requires_role`: `role = '담임'`이 아니면 `homeroom_grade`/
  `homeroom_class`가 반드시 NULL이어야 함 — 담임이 아닌데 학년·반이 남아있는 상태를
  DB 레벨에서부터 막았습니다.
- 새 RPC `admin_set_teacher_role(p_teacher_id, p_role, p_grade, p_class)` — 기존
  `admin_set_teacher_admin` 등과 같은 패턴으로 `perform public.assert_admin();`부터 하고,
  `p_role`이 `'담임'`이 아니면 grade/class를 서버에서 강제로 NULL 처리(클라이언트가 실수로
  값을 같이 보내도 안전).

### UI — 계정 관리 탭
각 교사 행을 2줄로 바꿨습니다: 1줄은 기존 그대로(이름/관리자·비번 상태/버튼들), 2줄을
새로 추가해서 "역할" 드롭다운(미지정/담임/부장/교감/교장/실무자) + (담임 선택 시에만)
학년·반 드롭다운 + "역할 저장" 버튼을 넣었습니다.
- 학년·반 드롭다운의 선택지는 이미 있던 "🏫 학급 구성" 탭의 `class_structure`
  (`{gradeCount, classCounts}`)를 그대로 읽어서 만듭니다(`gradeOptionsHtml`/`classOptionsHtml`) —
  즉 학급 구성 탭에서 "2학년은 7반까지"라고 설정해두면 담임 반 선택지도 자동으로 거기 맞춰집니다.
- 역할을 "담임"으로 바꾸면(`onTeacherRoleChange`) 학년·반 드롭다운이 나타나고, 학년을
  바꾸면(`onHomeroomGradeChange`) 그 학년의 반 개수에 맞춰 반 드롭다운이 다시 그려집니다.
- 자동 저장이 아니라 "역할 저장" 버튼을 눌러야 반영됩니다(다른 계정 관리 액션들과
  일관되게, 드롭다운 만지자마자 바로 DB에 쓰지 않도록).

### 확인한 방법
Playwright(`role-check.js`, 스크래치패드)로: 3명(교장 1, 담임 1(2학년 3반), 미지정 1)을 목
데이터로 넣고 계정 관리 탭을 열어서 각 행에 저장된 역할·학년·반이 정확히 채워지는지,
미지정 교사를 담임으로 바꾸고 학년을 3학년으로 바꿨을 때 반 드롭다운이 3학년 반 개수(7개)로
다시 그려지는지, "역할 저장"을 눌렀을 때 `admin_set_teacher_role` RPC가
`{p_teacher_id, p_role:'담임', p_grade:3, p_class:5}`로 정확히 호출되는지까지 확인하고
스크린샷으로 레이아웃도 확인했습니다.

### 다음 세션이 볼 것
- **실무자 전용 홈화면 구성은 아직 안 만들었습니다** — 사용자가 나중에 논의하자고
  명시했습니다. 논의할 때 참고할 것: `teachers.role`이 이제 DB에 있으니, 로그인 시
  `currentTeacher.role`을 같이 읽어와서(`sb.from('teachers').select(...)`에 `role` 컬럼
  추가 필요 — 현재 로그인 로직의 select 목록에는 아직 없음) 역할별로 다른 대시보드를
  보여주는 분기를 만들면 됩니다.
- 담임 역할이 실제 권한에 영향을 주지는 않습니다(순수 표시/데이터용) — 이전 라운드에
  물어봤던 "역할이 권한에 영향을 주는지"에 대한 답은 이번 요청으로 사실상 "아니오,
  표시용"으로 정리된 것으로 보입니다만, 부장/교감/교장한테 관리자 권한 일부를 자동으로
  주는 기능을 원하면 별도 요청이 필요합니다.

## 지금 막 끝낸 일 (2026-09-26.13) — 날씨 카드 가운데 빈 공간 제거, 학사일정 자동 스크롤(마퀴)

사용자가 최대화 창 스크린샷과 함께: "실제 날씨보면 최대 창으로 했을 때 가운데가 저렇게
비는데 좋은 방법 있어? 그리고 위에 다가오는 학사일정 저 글씨는 오른쪽에서 왼쪽으로 천천히
움직이게 할 수 있나?"

### 1. 날씨 카드 — 창을 넓게 했을 때 가운데가 뻥 뚫리는 문제
원인: 메인 정보 줄이 "아이콘+온도+날씨설명" 묶음(왼쪽)과 "미세/초미세" 묶음(오른쪽) 이렇게
두 덩어리만 있고 `justify-content: space-between`으로 양 끝에 붙여놨었습니다. 창을 넓히면
`.weather-group`(시계:날씨 = 4:6 비율)도 같이 넓어지는데, 두 덩어리는 내용만큼만 크니까
그 사이 남는 공간이 전부 가운데 한 곳으로 몰려서 "뻥 뚫린 구멍"처럼 보였습니다.
**고친 방법**: 최고/최저 기온을 아이콘+온도 블록에서 분리해서 독립된 세 번째 덩어리로
만들고(아이콘+온도, 최고/최저, 미세/초미세 — 총 3덩어리), 컨테이너를
`justify-content: space-evenly`로 바꿨습니다. 이러면 남는 공간이 세 덩어리 사이사이와
양 끝, 총 네 군데로 나뉘어 들어가서 "가운데 큰 구멍" 대신 "고르게 퍼진 여백"으로 보입니다.
- **시행착오**: 처음엔 세 덩어리를 `flex:1`로 균등 성장시켜서 폭에 맞춰 늘었다 줄었다
  하게 만들었는데, 기본 폭(약 208px)에서 오히려 각 덩어리가 필요한 만큼도 못 받아서
  온도("21°"→"2...")나 미세먼지 문구가 잘려버리는 **새 버그**가 생겼습니다. 좁은 폭에서
  "실측 없이 비율만 맞춰보고 넘어간" 실수를 또 반복한 것 — 결국 각 덩어리는 원래처럼
  내용 크기 그대로(`flex-shrink:0`) 두고, 남는 공간 분배 방식만 `space-evenly`로 바꾸는
  쪽으로 되돌렸습니다. 이러면 평소 폭(208px 안팎)에서는 내용이 꽉 차서 남는 공간이
  거의 없으니 기존과 똑같이 보이고, 창을 넓힐 때만 여백이 고르게 퍼집니다.
  **교훈**: "내용에 맞는 자연 크기 유지 + 남는 공간의 분배 방식만 바꾸기"가
  "억지로 비율에 맞춰 늘였다 줄였다 하기"보다 훨씬 안전하다 — 후자는 항상 실측을
  요구하고 좁은 폭에서 깨지기 쉽다.
- 아주 좁은 폭(예: 1280px 창, 날씨 영역이 116px까지 줄어드는 극단적 경우)에서는
  `overflow:hidden`을 준 바깥 줄이 오른쪽 덩어리(미세/초미세)부터 깔끔하게 잘라내도록
  안전장치만 남겨뒀습니다 — 겹쳐 보이던 예전 문제(글자가 서로 포개짐)는 없지만, 이 정도로
  극단적으로 좁히는 건 애초에 이 대시보드가 염두에 둔 사용 환경이 아니라서(전체화면 게시판용)
  더 손대지 않았습니다.

### 2. "다가오는 학사일정" — 오른쪽에서 왼쪽으로 흐르는 마퀴
`#upcoming-schedule-teaser`를 감싸는 `.schedule-marquee-wrap`(overflow:hidden)을 새로 만들고,
안의 `.schedule-marquee-track`에 `padding-left:100%; animation: schedule-marquee 26s linear
infinite;`를 줬습니다(`transform: translateX(0) → translateX(-100%)`). 이 방식은 트랙 폭이
"컨테이너 폭(패딩) + 실제 텍스트 폭"이 되고, 애니메이션 시작/끝 지점 둘 다 "글자가 완전히
안 보이는 상태"라서 무한 반복 시 이어붙는 지점이 튀어 보이지 않는 흔한 CSS 마퀴 기법입니다.
- 학사일정 항목 수를 3개(`slice(0,3)`)에서 8개(`slice(0,8)`)로 늘렸습니다 — 어차피 흘러가면서
  다 보여줄 수 있으니 예전처럼 "말줄임표로 잘릴까 봐" 3개로 제한할 이유가 없어졌습니다.
- `updateScheduleMarqueeState()`가 텍스트 실제 폭(`scrollWidth - 컨테이너폭`)을 재서, 컨테이너에
  다 들어갈 만큼 짧으면 `.no-scroll` 클래스를 붙여 애니메이션을 끕니다(짧은데 괜히 오른쪽에서
  기다렸다 흘러오는 게 어색해서). `window resize`에도 다시 재도록 디바운스(200ms)를 걸어서,
  창 크기를 바꿔도(=사용자가 말한 "최대화" 시나리오) 다시 계산됩니다.

### 확인한 방법
`round-f-check.js`(스크래치패드, NEIS 학사일정을 4건 mock)로: (1) 뷰포트 1920px에서 날씨
메인 줄 3덩어리 사이 공간이 골고루 퍼지는지 스크린샷으로, (2) 뷰포트 1280px(날씨 영역
약 116px)까지 좁혀도 글자가 서로 겹치지 않고 깔끔하게 잘리는지, (3) 기본 1600px에서
온도/설명/최고·최저/미세·초미세가 전부 안 잘리고 다 보이는지 — 이 세 폭을 모두 스크린샷으로
비교했습니다. 마퀴는 `getComputedStyle(...).animationName === 'schedule-marquee'`로 애니메이션이
실제로 붙었는지, `no-scroll` 클래스가 긴 텍스트(4개 항목 붙인 문자열)에서는 안 붙는지 확인했습니다.

### 다음 세션이 볼 것
- 날씨 카드 레이아웃을 만질 일이 있으면 **반드시 실제 컨테이너 폭을 먼저 재고**(약 208px가
  이 대시보드의 기본 폭입니다 — `getBoundingClientRect()`로 확인) 그 폭 기준으로 내용이
  다 들어가는지 스크린샷으로 확인한 다음에 커밋하세요. 이번 라운드에서만 이 실수를 두 번
  반복했습니다.
- 마퀴 애니메이션 속도(26초)는 감으로 정한 값입니다. 항목이 8개보다 훨씬 많아지거나
  텍스트가 아주 길어지면 사용자가 "너무 빠르다/느리다"고 할 수 있습니다 — 그때는 텍스트
  길이에 비례해서 `animation-duration`을 JS로 계산해 주는 것도 고려해보세요.

## 지금 막 끝낸 일 (2026-09-26.12) — .11 후속 미세조정: 급식 칸 높이 원복, 날씨 카드 디테일 보강

.11에서 만든 결과물에 대해 사용자가 스크린샷 2장(실제 화면 + 참고용 네이버 날씨 위젯)과 함께
바로 지적: "급식 칸을 저렇게 늘리라는게 아니라 그 전에보다 10~20px 정도 조금 높여달라는거지
저렇게 넓어봤자 뭐해. 그리고 날씨에서 저렇게 보여준 스크린샷처럼은 구성 못하는거야?"

### 1. 급식 칸 높이 — flex 비율이 아니라 고정 높이로
.11에서 `flex: 0 0 118px`(고정)을 `flex: 1.4`(비율)로 바꿨는데, 이게 문제였습니다 —
급식에 데이터가 적을 때(또는 이 세션의 급식 API 응답이 없을 때) 빈 공간이 사진 위젯만큼
커져버렸습니다. 사용자가 원한 건 "이전보다 살짝만 더 크게"였지 "화면을 꽉 채우게"가
아니었습니다. `flex: 0 0 136px`(기존 118px + 18px)로 되돌렸습니다 — 여전히 고정 높이라
메뉴가 많아도 늘어나지 않고 스크롤이 생기지만, 이전보다 확실히 여유가 생겼습니다.
**교훈**: "칸을 좀 늘려줘" 요청을 flex-grow 비율로 해석하면 "내용에 맞춰 큼직하게
자란다"는 의미가 돼버리는데, 사용자는 그냥 "몇십 px만" 처럼 고정폭 개념으로 말하는
경우가 많다 — 모호하면 작게(고정 px) 쪽으로 해석하는 게 안전하다.

### 2. 날씨 카드 — 참고 스크린샷(네이버 날씨류) 구조에 더 가깝게
- 미세먼지를 PM10 숫자 하나(`weather-dust-val`)로 뭉뚱그려 보여주던 것을, 참고 이미지처럼
  **"미세"(PM10)와 "초미세"(PM2.5)를 따로** 상태 단어(좋음/보통/나쁨/매우나쁨)로 보여주도록
  바꿨습니다. `fetchWeather()`가 air-quality API에 `current=pm10,pm2_5`를 같이 요청하고,
  새 `dustStatusFor(value, [보통기준, 나쁨기준, 매우나쁨기준])` 헬퍼로 PM10은
  `[30,80,150]`, PM2.5는 `[15,35,75]` 기준(한국 통합대기환경지수 구간)을 적용합니다.
  `#weather-pm10-status`/`#weather-pm25-status`에 텍스트로 들어갑니다.
- 오늘 최고/최저를 "최고 24° / 최저 15°"라는 긴 라벨 대신, 참고 이미지처럼
  **"15° / 24°"로 짧게, 최저는 파란색(#4C8DC2)/최고는 빨간색(#D9534F)** 으로 색만으로
  구분되게 바꾸고 아이콘+온도+날씨설명 바로 아래에 붙였습니다.
- 시간별 예보 칸의 세로 순서를 (시각→아이콘→온도)에서 참고 이미지와 같은
  **(온도→아이콘→시각)** 순서로 바꿨습니다.
- 폭이 여전히 좁아서(약 200px 안팎, .11에서 실측함) 참고 이미지에 있는 꺾은선 그래프,
  "예보 비교" 링크, 동 단위 실제 주소 같은 요소까지는 넣지 않았습니다 — 카드 정보

## 지금 막 끝낸 일 (2026-09-26.9) — .8 탭 콘솔의 레이아웃 버그 수정 + 정리

.8에서 관리자 설정을 탭 콘솔로 만들었는데, 사용자가 스크린샷 3장을 보내면서 **"이거
검토하고 만든거 맞아?"**라고 정당하게 화를 냈습니다. 실제로 학기 날짜·즐겨찾기 탭의
라벨("1학기")이 세로로 한 글자씩 쪼개져 보이고, 저장 버튼이 세로로 길게 늘어나
있었습니다 — 저는 그때 tt/duty 탭만 스크린샷으로 확인하고 나머지 4개 탭은 실제로
안 열어봤습니다(구조적으로만 맞으면 된다고 생각하고 넘어간 것 — 명백한 실수).

### 진짜 원인
`switchAdminTab()`에서 활성 탭 전체를 무조건 `display:flex`로 켰습니다. tt/duty
탭은 안에 꽉 채워야 하는 임베드 콘텐츠(그리드·목록)가 있어서 flex-column이 맞지만,
학기 날짜/즐겨찾기/계정/초기화 탭은 원래 위에서 아래로 쌓이는 평범한 block
레이아웃이었는데 flex로 강제로 바뀌면서 그 안의 직계 자식들(라벨, 입력칸들,
저장 버튼)이 **가로로 나란히 서는 flex item**이 되고 `align-items` 기본값(stretch)
때문에 버튼이 세로로 쭉 늘어난 것이었습니다. `tabId === 'tt' || 'duty'`일 때만
`flex`, 나머지는 `block`으로 고쳤습니다. **교훈: 탭/모달 UI를 만들 때는 만든 화면
"전부"를 하나씩 실제로 열어서 스크린샷으로 봐야 한다 — 일부만 확인하고 나머지는
"구조가 맞으니 괜찮겠지"라고 넘기면 안 됨.**

### 같이 정리한 것 (사용자 피드백 3개 더)

### 핵심 구조: "팝업을 새로 안 띄우고, 그 모달의 DOM 자체를 옮긴다"
시간표 관리(`#schedule-overlay`)와 감독표(`#duty-overlay`)는 **일반 교사가 홈 화면

`mountBox()`라는 함수로 그 모달의 실제 `<div class="modal-box" id="schedule-modal-box">`
/`id="duty-modal-box"` 엘리먼트를 `appendChild`로 관리자 설정 안의 슬롯
(`#admin-tt-slot` / `#admin-duty-slot`)으로 그대로 옮겨버립니다. **로직은 똑같은
함수를 그대로 재사용**합니다 — `openScheduleModal()`/`openDutyModal()`은 이제

`initDutyModalBody`)을 실행"하는 진입점 역할만 하고, 실제 fetch·렌더링 로직은
그대로입니다. **다음에 이 부분을 또 고칠 일이 있으면**: 모달 내용을 수정하고
싶을 때 `#schedule-overlay`/`#duty-overlay` 안의 마크업을 고치면 두 군데(독립 팝업 +
관리자 콘솔 임베드) 모두에 자동으로 반영됩니다 — 마크업을 두 벌로 복사해두지

### 1) 시간표가 "1학기/2학기 구분 없이 하나만 있던" 버그 → 진짜로 분리함

**증상**: 시간표 관리에서 2학기 엑셀을 올리면 1학기 시간표가 사라지고, 드롭다운을
"1학기"로 바꿔도 그대로 2학기 내용이 보였습니다. **원인**: `timetable` 테이블이
`teacher_name` 하나만 유니크 키로 써서 선생님 한 명당 시간표가 통째로 한 줄뿐이었고,
엑셀 업로드 때 보이는 "1학기/2학기" 드롭다운은 `app_settings.current_semester`에
라벨만 저장할 뿐 실제로는 아무 데도 안 쓰이는 표시용이었습니다(코드 툴팁에
"표시용으로만 씁니다"라고 정직하게 적혀 있었지만 아무도 그 뜻을 몰랐죠).

사용자에게 "둘 다 저장해서 언제든 전환"과 "학기 날짜를 관리자 설정에서 직접 등록"
두 가지를 확인받고 이렇게 고쳤습니다:

- **DB**: `timetable`에 `semester` 컬럼 추가, 유니크 키를 `(teacher_name, semester)`로
  변경(마이그레이션 `timetable_semester_split`, Supabase 프로젝트
  `pqreeimkjnphupqqwiqo`에 적용 완료). 기존 50줄은 마이그레이션 시점에
  `app_settings.current_semester`가 `'2학기'`였던 걸 확인하고 전부 `'2학기'`로
  태그했습니다. `admin_reset_timetable(p_semester)` RPC도 이름 그대로 "그 학기만"
  지우도록 고쳤습니다(예전엔 전체 삭제).
- **관리자 설정**에 "📅 학기 날짜 설정" 섹션을 새로 추가 — 1학기/2학기 시작일·종료일을
  직접 등록합니다(`app_settings.semester_ranges`에 저장). **이 날짜를 등록해야
  자동 학기 전환과 감독표 자동 채우기가 정상 동작합니다 — 아직 등록 전이라면
  꼭 관리자한테 등록해달라고 안내하세요.**
  (등록 전에는 `getActiveSemester()`가 등록된 시작일 중 가장 최근 걸 고르거나,
  아무것도 없으면 그냥 '1학기'로 fallback합니다 — 안 터지긴 하지만 정확하지 않음.)
- **"지금 몇 학기인지"는 오늘 날짜가 등록된 기간 중 어디 속하는지로 자동 판단**합니다
  (`getActiveSemester()`, `index.html` 안 `todoYmdDash`/`ensureSemesterRangesLoaded`
  근처). 대시보드(내 시간표/검색시간표)는 이 자동 판단값을 그대로 씁니다 — 그래서
  방학 중 다음 학기 시간표를 미리 올려놔도, 그 학기 날짜가 되기 전까진 화면엔 여전히
  지금 학기 게 보입니다.
- **시간표 관리 모달**에는 제목 옆에 1학기/2학기 탭이 새로 생겼습니다
  (`scheduleModalSemester` 상태, `switchScheduleModalSemester()`). 이 탭은 대시보드가

  독립적으로 동작합니다 — 모달 안에서 쓰는 데이터는 `window.modalSchedules`(대시보드가
  쓰는 `window.allSchedules`와 분리)라서, 관리자가 모달에서 1학기를 들여다봐도
  대시보드가 보여주는 화면은 안 바뀝니다. 엑셀 업로드 드롭다운도 이제 진짜로
  동작합니다(그 학기 탭과 자동으로 같이 움직임).
- 내 시간표 카드 제목 옆에 지금 보고 있는 학기 라벨(`#active-semester-label`)을
  작게 표시했습니다.
- Playwright로 가짜 Supabase를 붙여서 학기 전환 시 교사 목록이 실제로 바뀌는지,

  대화 기록에 전체 코드 있음 — 다음에 비슷한 검증할 때 참고하세요).

### 2) 감독표(야자/급식/아침) 입력이 너무 느렸던 것 → 학사일정으로 평일 자동 채우기

기존엔 "+ 한 줄 추가"를 학기 내내 수십~백 번 눌러서 날짜를 하나하나 골라야 했습니다.
이제 감독표 수정 모드에 **날짜 범위(기본값: 지금 학기 시작~종료일) + "📅 학사일정으로
평일 채우기" 버튼**이 생겼습니다. 누르면:

1. 그 범위의 **평일(월~금)만** 골라내고,
2. NEIS `SchoolSchedule`(학사일정) API를 그 범위로 조회해서 이벤트 이름에
   "휴업"/"방학"/"휴일"이 들어간 날짜는 뺍니다(`fetchAcademicVacationDates` —
   달력 화면에서 날짜를 빨갛게 표시할 때 쓰는 필터와 살짝 다르게 **"기념일"은 안
   뺐습니다** — 기념일이어도 보통 정상 등교하는 평일이라 감독이 필요할 수 있어서).
3. 이미 저장돼 있거나 이미 화면에 추가돼 있는 날짜는 건너뛰고,
4. 남은 날짜들을 이름 빈칸인 채로 쭉 깔아줍니다(`fillDutyRowsFromAcademicCalendar`).

사용자가 "감독이 없는 날도 있을 수 있다"고 한 부분을 위해 **저장 로직도 같이
고쳤습니다**: 예전엔 빈 줄이 하나라도 있으면 저장 자체를 통째로 막았는데(`invalid`
체크), 이제는 **이름이 채워진 줄만 저장하고 빈 줄은 조용히 건너뜁니다**
(`saveAllPendingDutyRows`) — 그래서 관리자가 평일을 통째로 깔아놓고 감독이 있는
날짜만 이름을 채운 뒤 바로 저장하면 됩니다. 날짜가 비어있는 줄(수동으로 만든 빈 줄을
안 지운 경우)만 여전히 막습니다.

Playwright로 가짜 NEIS 응답을 흘려서 "평일만 골라지는지 / 방학일이 빠지는지 /
빈 이름 줄이 있어도 저장이 막히지 않는지" 확인했습니다(`dutycheck2.js`, 마찬가지로
스크래치패드).

### 폰트 정체를 드디어 찾음 (2026-09-26.5) — "부광고ON"은 movingclass였습니다

사용자가 스크린샷으로 스마트보드 화면과 "부광고ON" 탭을 나란히 띄워서 보여줬는데,
그 탭의 실제 주소가 `08hwichemi.github.io/movingclass/`였습니다 — **면접ON이
아니라 `08hwichemi/movingclass`(앱 이름 자체가 "부광고ON", Expo/React
Native 앱)였습니다.** 소스 저장소 `08hwichemi/movingclass-src`를 clone해서
찾아보니, 코드 어디에도 `fontFamily`를 직접 지정한 곳이 없었습니다 — 그런데도
빌드된 결과물(`_expo/static/js/web/index-*.js`)을 뒤져보니 이런 게 있었습니다:

```
body, body [class], input, textarea, button, select {
  font-family: 'IBM Plex Sans KR', 'Malgun Gothic', system-ui, sans-serif;
}
```

즉 **개발자가 일부러 고른 폰트가 아니라 react-native-web이 기본으로 깔아주는
스타일**이었는데, 그게 우연히 "IBM Plex Sans KR"이라는 뚜렷한 폰트였고, 사용자
눈에는 그게 "부광고ON의 느낌"으로 각인된 것 같습니다. 구글 폰트에 정식으로 있는
폰트라서(`https://fonts.googleapis.com/css2?family=IBM+Plex+Sans+KR:wght@400;500;600;700&display=swap`),
Pretendard CDN 링크를 통째로 이걸로 바꿨습니다 — `body`의 `font-family`도
`"IBM Plex Sans KR", "Malgun Gothic", "Apple SD Gothic Neo", system-ui,
-apple-system, BlinkMacSystemFont, sans-serif`로 맞췄습니다. Playwright로
`document.fonts.check('16px "IBM Plex Sans KR"')`가 `true`인 것까지 확인했고,
스크린샷으로도 눈에 띄게 다른 서체로 렌더링되는 걸 확인했습니다(더 이상 Pretendard는
전혀 안 씁니다 — 관련 CDN 링크·font-family 다 제거됨).

**주의**: IBM Plex Sans KR은 구글 폰트 기준 최대 굵기가 700(Bold)까지입니다.
이 화면 CSS 곳곳에 `font-weight: 800`/`900`을 쓰는 곳이 많은데, 그 굵기는
브라우저가 700 폰트를 가지고 합성(synthetic bold)해서 흉내 냅니다 — 대부분
브라우저에서 눈에 띄게 어색하진 않지만, 나중에 "제목 글씨가 너무 두꺼워 보인다"는
피드백이 오면 이게 원인일 수 있습니다(그럴 땐 800/900을 700으로 낮추면 됩니다).

## 코드 구조

`index.html` 하나가 전부입니다 (위젯 스타일 + 데이터 불러오기 로직이 한 파일).
서버와 통신하는 부분만 `gas`로 시작하는 함수들(`gasGetDuty`, `gasSetDuty`,
`gasGetNotice`, `gasSetNotice`, `gasGetSchedule`, `gasSetSchedule` 등)에 모여 있고,
나머지(날씨·급식·학사일정·캘린더 메모·즐겨찾기)는 그대로 `localStorage`나
공개 API(open-meteo, 나이스)를 씁니다 — 원래 구글 앱스크립트 버전에서 그대로 가져온
부분이라 건드리지 않았습니다.

그 외에 저장소 맨 위에 `version.txt`(현재 배포된 판 번호, `index.html`의
`BUILD_ID`와 짝을 이룸)와 `tools/판올리기.py`(새 판 올릴 때 그 둘을 한 번에
맞춰주는 스크립트)가 있습니다. `index.html`을 고친 뒤 커밋하기 전에
`python3 tools/판올리기.py`를 실행하는 걸 잊지 마세요 — 안 그러면 이미 열려있는
탭에 새로고침 띠가 뜨지 않습니다.
