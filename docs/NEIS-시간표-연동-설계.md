### 중요하게 새로 발견한 문제 — 교사 시간표에 학년·반 정보가 없다

기존 `timetable` 테이블(선생님이 직접 입력하거나 엑셀로 올리는 시간표)은 칸마다 **"과목명 + 교실 번호"**만
있고, 그 수업이 몇 학년 몇 반인지는 저장하지 않는다. 그런데 §5의 자동 매칭 로직은 "(학년-반, 과목)으로
교사를 역조회"하는 것을 전제로 한다 — 즉 교사 시간표 쪽에도 학년·반 정보가 있어야 나이스 학급 시간표와
맞대조할 수 있다.

업로드받은 "2026학년도 2학기 전체 선생님 시간표" 엑셀을 보면, **교실 번호가 우연히 학년·반과 같은 패턴으로
보인다** (예: "303" 교실 = 3학년 3반, "107" 교실 = 1학년 7반). 부광고가 이동수업 없이 반 교실에서 수업하는
방식이라면 이 추정이 맞을 수 있지만, 특별실(음악실·보건실 등)을 쓰는 과목도 섞여 있어서 **항상 맞는다는
보장은 없다.** 이 추정을 자동 반영에 그대로 쓰면 안 되고, 진짜 학년·반 데이터를 어떻게 확보할지(교실 번호
추정을 쓸지, 엑셀 양식에 학년·반 칸을 추가해달라고 할지) 먼저 사람이 정해야 한다.

**정리: 다음 사람이 결정해야 할 것**
1. "🛰️ 나이스 확인(시험)" 버튼으로 실제 응답을 확인하고 필드 이름을 맞춘다.
2. 교실 번호 = 학년·반이라는 추정이 이 학교에서 실제로 항상 맞는지 확인한다 (또는 다른 방법을 찾는다).
3. 그 다음에야 §5의 자동 반영(교사 역조회 → 자동 배정 / 확인 필요)을 만들 수 있다.

## 1. 배경과 목표

- 기존 학교 대시보드가 있고, 서버는 Supabase + GitHub로 이전 완료된 상태.
- 기존 방식: 교사별 시간표를 관리자(사용자)가 구글 시트에 수동 입력. 급식과 학사일정은 이미 NEIS Open API로 가져오고 있음.
- 목표: **교사별 시간표는 관리자가 엑셀로 업로드**하고, **NEIS의 학급 시간표를 주기적으로 받아서 변경을 감지**해 교사별 시간표에 자동 반영한다. 시간표 담당자는 NEIS만 수정하면 되도록 하는 것이 핵심.

## 2. NEIS 교육정보 개방 포털 API 요약

기본 주소: `https://open.neis.go.kr/hub/{서비스명}` (인증키 `KEY`, `Type=json`, `pIndex`, `pSize` 사용. 키가 없으면 5건만 반환, 키가 있으면 `pSize` 최대 1000).

| 용도 | 서비스명 |
|---|---|
| 학교 기본정보 | `schoolInfo` |
| 학급 정보 | `classInfo` |
| 학사일정 | `SchoolSchedule` |
| 급식 | `mealServiceDietInfo` |
| 시간표 | `elsTimetable`(초) / `misTimetable`(중) / `hisTimetable`(고) / `spsTimetable`(특수) |

공통 필수 파라미터: `ATPT_OFCDC_SC_CODE`(교육청 코드), `SD_SCHUL_CODE`(학교 코드).
시간표 주요 파라미터: `AY`(학년도), `SEM`(학기), `GRADE`, `CLASS_NM`, `ALL_TI_YMD`(일자) 또는 `TI_FROM_YMD`~`TI_TO_YMD`(기간).
시간표 주요 응답 필드: 일자, 학년, 반, 교시(`PERIO`), 수업내용/과목명(`ITRT_CNTNT`).

> 주의: 위 파라미터·필드명은 기억에 기반한 것이므로, 구현 전에 **실제 호출로 응답 구조를 확인**할 것.
> → 2026-09-25: `index.html`의 "🛰️ 나이스 확인(시험)" 화면이 바로 이 확인을 위한 도구다. 아직 실제로 확인은 못 했다 (위 "진행 상황" 참고).

## 3. NEIS 시간표 API의 한계 (설계의 전제)

1. **교사 정보가 없다.** 학년·반·교시·과목명만 오고 교사명은 오지 않는다. 그래서 교사별 시간표는 NEIS만으로 만들 수 없다.
2. 학교가 NEIS에 시간표를 입력해 둬야 데이터가 나온다. 입력 시점에 따라 학기 초 공백이나 반영 지연이 있을 수 있다.
3. 응답은 **현재 시점의 값**이고 변경 이력은 주지 않는 것으로 알고 있다(미검증). 그래서 변경 감지는 **우리가 이전 스냅샷을 저장해 두고 비교**해야 한다.
4. 고등학교는 선택과목·이동수업 때문에 반 기준 데이터가 지저분할 수 있다.
5. 보강·임시 변경을 학교가 NEIS 밖에서 따로 관리하면 API에 변화가 없어 감지할 수 없다(미검증).

## 4. 데이터 흐름

```
[관리자 엑셀 업로드]  → teacher_timetable (교사·요일·교시·학년·반·과목)
[NEIS API 정기 호출]  → neis_timetable_snapshot (학급 기준 시간표 스냅샷)
                              │
                     이전 스냅샷과 비교(diff)
                              │
                     changes (바뀐 칸 목록)
                              │
        teacher_timetable 역조회로 교사 특정 → 자동 반영 or "확인 필요"
```

## 5. 변경 반영 로직

연결 키: **학년 + 반 + 요일(일자) + 교시**. 교사 시간표의 "3-2 수요일 3교시 수학"과 NEIS의 "3-2 수요일 3교시"는 같은 칸이다.

1. NEIS 시간표를 받아 저장된 스냅샷과 비교해서 **과목명이 달라진 칸**을 뽑는다.
2. 바뀐 칸마다 `(학년-반, 새 과목)`으로 교사 시간표를 역조회해 담당 교사 후보를 찾는다.
3. 예시: 3-2 수요일 3교시가 수학→체육, 목요일 5교시가 체육→수학으로 바뀌면, 3-2 체육은 박OO, 수학은 김OO이므로 **맞교환**으로 판단하고 교사별 시간표를 갱신한다.
4. 반영 전 **검증**: 갱신 후 한 교사가 같은 시간에 두 반에 들어가지 않는지, 맞교환이면 양쪽이 논리적으로 맞물리는지 확인한다.

### 자동 반영 조건
- `(학년-반, 과목명)`으로 교사가 **유일하게** 결정되고, 충돌 검증을 통과할 때.

### 자동 반영하지 말고 "확인 필요"로 남기는 경우
- 그 반에 해당 과목을 가르치는 교사가 데이터에 없을 때(원래 없던 과목 유입).
- 같은 반·같은 과목을 교사 둘 이상이 나눠 맡을 때(분반, 공동교수, 초등 전담 등).
- 갱신 시 교사 시간 충돌이 생길 때.
- 한쪽 칸만 바뀌고 짝이 없을 때(보강·자습 전환 가능성).

원칙: **애매하면 멈춘다.** 잘못된 교사가 자동으로 박히는 것보다 확인 목록에 올리는 쪽이 안전하다.

### 과목명 정규화
NEIS 과목명과 교사 엑셀의 과목명 표기가 다를 수 있다(예: "수학" vs "수학Ⅰ"). **별칭 사전 테이블**(`subject_alias`)을 두고 비교 전에 정규화한다.

## 6. Supabase 스키마

- `timetable` (이미 있음): teacher_name, cells(jsonb, 35칸 = 월~금 × 1~7교시, "과목\n교실" 문자열). **학년·반 정보 없음 — 위 "중요하게 새로 발견한 문제" 참고.**
- `neis_timetable_snapshot` (2026-09-25 생성 완료): fetched_at, class_date, grade, class_no, period, subject, raw(jsonb, 원본 응답 보관용)
- (아직 안 만듦) `timetable_changes`: date, grade, class_no, period, old_subject, new_subject, candidate_teachers, status(`auto_applied` / `needs_review` / `resolved`), detected_at
- (아직 안 만듦) `subject_alias`: alias, canonical

## 7. 구현 시 유의사항

- **NEIS 인증키는 저장소에 커밋하지 말 것** — 이라고 원래 적혀 있었지만, 실제로는 이미 `index.html`에 평문으로
  박혀 있다(급식·학사일정에도 이미 쓰던 키라 이번에 새로 노출된 건 아니다). 로그인 없는 공개 화면이라는 이
  프로젝트의 전제상 큰 문제는 아니지만, 키를 숨기고 싶다면 Supabase Edge Function 뒤로 옮겨야 한다.
- 주기 실행(예: 매일 아침)은 Supabase Edge Function + 스케줄러 또는 GitHub Actions 중 편한 쪽으로. (2026-09-25 기준: 아직 수동 버튼만 있고 자동 스케줄은 없음)
- 날짜 기준: 이번 주와 다음 주 정도의 기간으로 호출해서 스냅샷을 비교하면 충분하다.
- 교사 시간표 업로드 시 엑셀 컬럼 검증(빈 값, 중복 교시)을 넣는다.

5. 고등학교라면 선택과목·이동수업이 NEIS에 어떻게 입력되어 있는지.
